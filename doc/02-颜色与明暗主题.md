# 02 · 颜色与明暗主题

## 1. 色彩系统的结构

【官方】HeroUI Native 不向组件暴露一套庞大的原始色阶，而是以少量语义角色覆盖绝大多数界面需要。主题使用 OKLCH，颜色名表达用途；无后缀变量通常代表背景，有 `-foreground` 后缀的变量代表置于该背景之上的文字或图标。

```text
原始色（white / black / snow / eclipse）
        ↓
主题语义色（background / surface / accent / danger…）
        ↓
派生色（hover / soft / secondary / tertiary…）
        ↓
组件槽位（Button 根、Label、Surface、Field、Indicator…）
```

## 2. 模式无关原始色

| Token | OKLCH | 近似 sRGB | 用途 |
|---|---|---|---|
| `--white` | `oklch(100% 0 0)` | `#FFFFFF` | 绝对白 |
| `--black` | `oklch(0% 0 0)` | `#000000` | 绝对黑、遮罩基底 |
| `--snow` | `oklch(0.9911 0 0)` | `#FCFCFC` | 深色主前景、彩色深底前景 |
| `--eclipse` | `oklch(0.2103 0.0059 285.89)` | `#18181B` | 浅色主前景、明亮状态底前景 |

近似十六进制仅便于沟通；实际主题应保留源码中的 OKLCH。

## 5. 为什么深色不是浅色反相

【源码 + 归纳】两套模式保留相同语义顺序，但用不同方式表达层级：

- 浅色：灰画布 `#F5F5F5` 上放白 Surface，并允许很轻的外投影。
- 深色：近黑画布 `#060607` 上放 `#18181B → #232325 → #262728` 的亮度阶梯。
- 浅色 Surface 有多层低透明度阴影；深色普通 Surface 和 Field 的阴影为透明。
- 深色 Overlay 用 `1px` 级白色 20% 内描边感，而不是保留浅色黑色投影。
- Warning 在深色模式更亮，Danger 更收敛，保证视觉重量与可读性不失控。

因此深色主题应重新校准每一层的亮度、色度与前景，不要对浅色截图执行颜色反相。

## 6. 表面与背景的配合规则

| 组合 | 用途 | 文本 | 边界/阴影 |
|---|---|---|---|
| `background + foreground` | 页面根、无容器正文 | foreground；次级 muted | 通常无阴影 |
| `background + surface` | 主卡片、成组内容 | surface-foreground | 浅色轻 shadow；深色靠亮度差 |
| `surface + surface-secondary` | 输入、嵌套摘要、选中前的中性层 | 对应 surface 前景 | 不再叠加强阴影 |
| `surface-secondary + surface-tertiary` | 按下、深一层嵌套 | foreground | 仅必要时细分隔 |
| `backdrop + overlay` | Dialog、Menu、Popover、Sheet | overlay-foreground | overlay shadow / 深色内缘 |
| `default + default-foreground` | 中性按钮、Tabs 底、普通控制 | default-foreground | 通常无强边界 |
| `accent + accent-foreground` | 单一主行动 | 配对前景 | 不再加品牌色描边 |
| `status-soft + status-soft-foreground` | 轻量状态、Chip、Alert 标题 | 状态色文字 + 普通描述 | 不把整块内容染成实色 |

不要把 `surface` 当“任何白色块”，也不要把 `overlay` 用作普通页面卡片；它们在深色主题和玻璃主题中的材质行为不同。

## 7. 自动派生规则

【源码】`theme.css` 用 `color-mix(in oklab, …)` 从少量基色生成状态：

| 派生 Token | 公式 |
|---|---|
| `background-secondary` | `background 96% + foreground 4%` |
| `background-tertiary` | `background 92% + foreground 8%` |
| `background-inverse` | `foreground` |
| `surface-hover` | `surface 92% + surface-foreground 8%` |
| `default-hover` | `default 96% + default-foreground 4%` |
| `accent/success/warning/danger-hover` | 对应底色 90% + 对应前景 10% |
| `*-soft` | 状态色 15% + transparent |
| `*-soft-hover` | 状态色 20% + transparent |
| `default-soft` / hover | default 50% / 60% + transparent |
| `separator-secondary/tertiary` | surface 85%/81% + surface-foreground 15%/19% |
| `border-secondary/tertiary` | surface 78%/66% + surface-foreground 22%/34% |

字段派生值：

```css
--color-field-hover: color-mix(in oklab, var(--field-background) 90%, var(--field-foreground) 2%);
--color-field-focus: var(--field-background);
--color-field-border-hover: color-mix(in oklab, var(--field-border) 88%, var(--field-foreground) 10%);
--color-field-border-focus: color-mix(in oklab, var(--field-border) 74%, var(--field-foreground) 22%);
```

CSS Color 的百分比总和不足 100% 时会按规范归一/引入透明度语义；实现中应保留源码表达，不建议先手工换算成固定十六进制。

## 8. Soft 前景与 Vibrant 主题

默认 `theme.css` 为不同状态设置了不同混色比例：

- Accent / Danger soft foreground：状态色 80% + foreground 20%。
- Warning soft foreground：状态色 65% + foreground 35%。
- Success soft foreground：状态色 70% + foreground 30%。
- Default soft foreground：直接使用 `default-foreground`。

可选的 `heroui-native/styles/vibrant` 只把四个彩色 soft foreground 改为“状态色 92% + foreground 8%”，提高品牌色饱和度；它不改变状态背景、页面背景或核心语义结构。Vibrant 适合品牌展示感更强的产品，不应作为增加界面彩度的万能开关。

## 9. 阴影值

### 浅色

```css
--surface-shadow:
  0 2px 4px rgba(0,0,0,.04),
  0 1px 2px rgba(0,0,0,.06),
  0 0 1px rgba(0,0,0,.06);

--overlay-shadow:
  0 2px 8px rgba(0,0,0,.02),
  0 -6px 12px rgba(0,0,0,.01),
  0 14px 28px rgba(0,0,0,.03);

--field-shadow: 与 surface-shadow 相同；
```

### 深色

```css
--surface-shadow: transparent;
--field-shadow: transparent;
--overlay-shadow: 0 0 1px rgba(255,255,255,.2) inset;
```

视觉结论：普通内容层不要“浮得很高”；强高程专属于临时浮层。

## 10. 对比度审计

以下为将 OKLCH 转成 sRGB 后的近似 WCAG 对比度，主要用于风险发现，不替代真机、色彩管理和组件状态测试。

| 配对 | 约对比度 | 判断 |
|---|---:|---|
| 浅色 foreground / background | 16.25:1 | 充足 |
| 浅色 foreground / surface | 17.72:1 | 充足 |
| 浅色 muted / background | 4.43:1 | 略低于普通文本 4.5:1；关键说明不要放这里 |
| 浅色 muted / surface | 4.83:1 | 可满足普通文本 4.5:1 |
| snow / accent | 3.59:1 | 满足 3:1，但不满足普通文本 4.5:1 |
| snow / 浅色 danger | 3.48:1 | 满足 3:1，但不满足普通文本 4.5:1 |
| eclipse / accent | 4.81:1 | 对比更高，但会改变官方视觉方向 |
| eclipse / 浅色 danger | 4.96:1 | 对比更高，但需重新评估危险语义与品牌感 |
| 深色 foreground / background | 19.79:1 | 充足 |
| 深色 foreground / surface | 17.27:1 | 充足 |
| 深色 muted / background | 7.72:1 | 充足 |
| 深色 muted / surface | 6.74:1 | 充足 |
| snow / 深色 danger | 4.35:1 | 接近但仍低于 4.5:1 |

【通用扩展】生产系统应加入以下门禁：

- 普通文字 4.5:1；大号/粗体大字和关键非文本图形至少 3:1。
- 按钮的 14/16px medium 文本仍按普通文本检查，不因为“看起来粗”自动降为 3:1。
- 若保留官方 Accent，可增大按钮标签尺寸/字重并复核是否达到“大文本”条件，或调整 Accent 亮度/前景色。
- 禁用态可以降低强调，但不能让仍需阅读的信息不可读；禁用状态不只依赖透明度表达。
- 错误、警告和成功必须同时配文字或图标，不得只靠红/黄/绿。

## 11. 色彩使用配额

【通用扩展】为了保持 Hero 风格，可采用经验配额：

- 70–85%：`background / surface` 等中性大面积。
- 10–25%：`surface-secondary / tertiary / default` 等结构层。
- 2–8%：Accent、状态色、焦点和选中标记。

这不是像素级硬规则，而是审图工具：如果首屏 30% 以上面积都被 Accent 覆盖，通常已经失去“强调稀缺”的层级优势。
